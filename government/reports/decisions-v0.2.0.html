A · Item 23b — honest receipt labels: before the tag, or after?

What it is

When a message is delivered to a Claude seat over its inbox socket, the daemon writes a durable receipt row acked (reader=<seat>) at the moment of injection. That row proves the bytes reached the seat's socket — it does not prove the seat read them, because Claude's runtime sends nothing back on success. By contrast, Copilot's RPC returns a messageId (a real ack), the Telegram bridge acks explicitly, and an echo reply is proof of reading. Item 23 (already live) added the honest sent outcome on the transport side; 23b would label who wrote the marker (daemon vs reader) so nothing downstream over-trusts acked.

What is true today

  • Nothing is lost or duplicated because of this — it is a meaning gap, not a delivery gap.
  • The spec erratum on #311 already states it plainly, so Jordan's agents will read the correct semantics.
  • Cost to build: s392 stream, adapter + CLI + docs, roughly 2–3 hours including review; it touches the daemon, so it needs a restart to go live.
