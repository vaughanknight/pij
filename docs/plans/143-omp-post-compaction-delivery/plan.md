# Plan 143 — mail survives an omp compaction (post-compaction delivery)

Owner: pij-minor-unicorn (prime). Ruling: Jordan 2026-09-09 — "lets get the post compaction fix in", after pij-involved-egret sat on an undelivered message for six minutes while compacting. Second incident of this shape (kotallo 2026-09-08, plan in docs/plans/archive/misc/omp-redeliver-2026-09-08/). Operator mitigation already applied: `compaction.methodOrder: [soft]` in ~/.omp/agent/config.yml (remote compaction off). This plan makes the extension robust regardless.

## Problem (verified live 2026-09-09, daemon 32033, seat pij-involved-egret, omp 18.1.14, pid 69412)
1. 13:34:13 omp remote compaction 404s (enterprise endpoint), falls back locally.
2. 13:34:23 daemon pushes message a369065ede1c90e1-…-0012 (spine 24789/24790, `queued/extension-stream`). The extension's push handler does not run: NO claim until 13:40:05, when the human typed a new turn. The 1 s mail ticker (`MAIL_STATUS_TICK_MS`, rust-runtime.ts:67) only polls when `inboxPending` is already set (rust-runtime.ts:283), and nothing sets it on compaction.
3. After the claim the custom-message inject (`pi.sendMessage` customType pij, deliverAs steer) is never observed: no `message_start` with the pijMessageId, so `pending.consumed` (rust-runtime.ts:375) never flips, no ack, footer `📨 1 pending` for 10+ minutes, the serial queue behind it head-blocked (1 row). Resend (`recoverUnconsumed`, :731) requires `pi.isIdle()` for ≥10 s, and the seat was busy on human turns.
4. Meanwhile the human had the seat run `pij-rs inbox --peek`; it read the body and acted on it. The extension cannot know that; the eventual idle resend will deliver it a second time.

The omp-side root cause (custom-message drain dead after a failed remote compaction) is upstream and unfiled (Jordan's call); this plan does not touch omp.

## Acceptance
- AC1 Compaction re-poll: on `session_compact` (and on `session_before_compact` → `session_compact` bracket end), the extension sets `inboxPending = true` and kicks `recoverInbox` on the next tick, so a message pushed during compaction is claimed within 2 s of compaction end without any human turn. Also re-poll on `turn_start`/`agent_end` if `inboxPending` is false and the last daemon push arrived during a compaction window (belt and braces; cite which one fired in the test).
- AC2 Boundary resend while busy: an injected-but-unobserved message is resent through the PROMPT path (existing `inject(..., "immediate", id, attempt)` resend form) at the first observed agent boundary after injection (`tool_result`, `turn_end`, or `agent_end`), not only after 10 s idle. The idle rule stays as the fallback when no boundary occurs. `MAX_RESENDS` unchanged (3), parked outcome unchanged. A resend must never fire while `session_before_compact` is open (would be swallowed again) — queue it for `session_compact`.
- AC3 Consumed elsewhere: heartbeat and re-claim responses carry the job's daemon state; if the daemon reports the job `done`/acked (e.g. the seat's own `pij-rs inbox` CLI claim+ack, a parent `inbox release`, or a park), the extension drops it from `pendingConsumption` with NO resend and clears the footer count. Daemon change allowed only if `/v1/inbox/heartbeat` does not already return state — if it does not, add `state` to its response (crates/daemon/src/delivery/mod.rs `heartbeat_inbox`) and a golden update.
- AC4 Tests (vitest, `.pi/extensions/pij/adapters/rust-runtime.test.ts` or its existing sibling): RED first for each — (a) push during compaction → claimed ≤2 ticks after `session_compact`, zero claims during the window; (b) inject unobserved + `tool_result` → prompt-path resend attempt 1 while `isIdle()` is false; (c) inject unobserved + heartbeat says `done` → dropped, no resend, status cleared; (d) control: observed inject (`message_start` with the id) → no resend on the next boundary. Name each test after the claim.
- AC5 Live proof on an ISOLATED daemon (never 127.0.0.1:7461) with an omp seat started in THIS worktree (`omp` from the worktree cwd loads the worktree's `.pi/extensions/pij`; `PIJ_RS_ADDR` to the isolated daemon): send while the seat runs `/compact`; cite claim seq and ack seq relative to compaction end. For AC2 live: a test-only fault switch `PIJ_TEST_SWALLOW_INJECT=1` that makes the omp adapter drop the custom message (documented as test-only in the adapter, refused in production when `NODE_ENV=production` is not required — just name it clearly); show the boundary resend landing on a busy seat. Report the exact commands and seqs.
- AC6 Docs: docs/how/pij-rs-api.md delivery section (or the extension's how-doc if one exists) gains "Compaction and resend" — the three rules above in five lines. Skill peer route touched only if it states a wait rule that is now wrong.
