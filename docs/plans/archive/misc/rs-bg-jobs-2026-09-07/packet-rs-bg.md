## What it is (legacy, .pi/extensions/pij/core/bg.ts + core/cli.ts ~:3536-3670)
`pij bg create --title "<what>" --command "<shell>" [--json]` runs a command detached (own process group), writes full output to `<outDir>/<jobId>.log`, returns `{job, title, pid, outPath}` and the human line "bg started — <title> (job <id>, pid <pid>); result will arrive as an injected turn from pij-bg; full output at <path>". On exit, a turn is delivered to the CALLER from sender `pij-bg` (BG_ACTOR — deliberately not the caller, so it is not self-send): `buildBgDoneTurn`/`buildBgKilledTurn` shapes in core/bg.ts (title, exit code, duration, last N lines, `full log: <path>` pointer — "full output is written to a file and POINTED at; only a short tail rides inline"). `list` (running/finished jobs of the caller), `tail <job>` (last lines of the log), `kill <job>` (SIGTERM the group, then a KILLED turn). Today on rs every leaf fails: create ⇒ E-NOID (legacy registry), list/tail/kill ⇒ "background jobs are unavailable in this build". Skill: 00-routing.md § C7 names `bg` as the way to run slow commands.
