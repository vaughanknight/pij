## Per-claim review

1. **Linux executable identity — needed, not redundant.** Main's Rust `read_native_process` already reads `/proc/<pid>/exe` and NUL-delimited argv (`crates/daemon/src/registration.rs:837–880`). This PR does not change that observer. It repairs the independent JavaScript extension-side nomination (`.copilot/extensions/pij/extension.mjs:24–38`), which otherwise fails to find the Copilot ancestor when Linux reports `MainThread` before the daemon can attest it. Tests distinguish a real Copilot executable with misleading comm from an unrelated executable named copilot. Linux-only cases skip on macOS; CI originally did not invoke this node:test suite, hence the added sensor.

2. **Foreground completion ancestry — needed.** `NativeCompletion.observe` now follows a foreground user only when its parent is an observed owned foreground `assistant.turn_end` and both native message and interaction IDs exist (`store.mjs:483–519`). The new user is not completion: the barrier still requires an owned terminal `session.idle`/`session.error`. It changes the interaction anchor, allowing foreground callbacks with omitted permission ancestry to reconnect. Tests prove no new claim at chained user/turn-end and reject unrelated parent, direct owned-user parent, subagent user, and missing interaction ID (`store.test.mjs:1586–1654`).

3. **Dead-address resume plus bootstrap retirement — risky ownership change, justified by independent incarnation proof.** The only new permission in `check_native_roster` is existing-address supersession when the exact requested native session matches an independently observed dead native target (`registration.rs:700–711`). The following guards remain in force:
   - `verify_native_host` independently validates the incoming executable and actual pane ancestry, sandwiches observation with pid/start checks, and rechecks the pane (`216–292`); the new owner is not trusted merely because its request names a PID.
   - `observe_dead_native_owners` considers only attested, non-relay, untombstoned native Copilot owners with a complete nonzero tuple; the exact incoming tuple is excluded. A live old tuple returns its unchanged start and is not marked dead. An absent process or different start means the old *incarnation* is gone, even if its PID is occupied by another process. Reported adapter errors propagate, never become death (`146–214`); the adapter's empty-output assumption is qualified below.
   - Before mutation, the roster is reread under the registration lock and each death witness is compared to current harness, process tuple, pane, native session, spawn binding, attestation, relay and tombstone fields (`351–373`, `679–688`). Concurrent ownership changes refuse; fresh operator metadata is retained by cloning the current row.
   - The bootstrap predecessor must be active, non-relay Copilot, on the exact incoming pid/start tuple and pane, and have a distinct nonempty native session (`712–729`). An unrelated live owner cannot be retired.
   - Target harness/session/tombstone/process checks, exact spawn binding, and every other live row's process/session/pane uniqueness checks remain (`735–797`). The saved address is updated in place; only the same-host bootstrap is tombstoned. Queued jobs are not deleted or retargeted (`537–629`).

   These refusal checks are **one-directional safety interlocks (brakes)**: removing them permits the same or more ownership transfers/retirements. They are not an age/retention policy. Plan 095's applicable safety principle is exact process identity and unknown-not-dead; its older TypeScript snapshot implementation is not the current Rust API. Existing tests explicitly cover recycled PIDs, unchanged live owners, observation failure and ownership-change races (`1772–1814`, `1845–1907`, `1985–2003`); the added seven-case bootstrap test covers the success and six mutation-free refusals (`1715–1770`). No new live-owner displacement bypass was found under the existing adapter contract.

   **Inherited proof limit — empty failed `ps`.** The real `ProcLiveness` adapter (`crates/harnesses/src/proc.rs:68–139`) correctly returns errors for command launch failure, permission-denied stderr, malformed/non-UTF-8 rows, and failed commands that produced a row. But `PsRunner` retains only `status.success()`, and `classify` returns `Ok(None)` for empty stdout plus empty stderr without inspecting that success flag. Its existing `an_absent_exact_pid_is_none` test deliberately covers the ordinary missing-PID shape. [INFERENCE] A signal-killed `ps` that produced no output has the same retained shape and could falsely authorize a dead-owner handoff despite a live old owner. This predates #375 and was not changed here. Smallest hardening: preserve exit code/signal, recognize only supported platforms' normal missing-PID outcome as absence, and refuse signal termination/other failures; add negative fixtures beside the existing absent/permission cases. Reported to the prime before final delivery; no out-of-scope product edit was made.

4. **Rollover explicit semantic Hold — needed after #374.** A staged `/new` draft no longer inhibits native delivery. The smoke explicitly sets Hold on its owned predecessor before enqueue, confirms the report, and requires the new successor not to be held. Its later old-target assertions therefore test native-session isolation rather than accidentally passing because the successor inherited Hold (`harness/scripts/copilot-native-smoke.ts:1974–1983`, `2024–2030`). Actual local-provider manual rollover passed: predecessor `pij-tiny-vosill` held, successor `pij-reasonable-excuse` unheld, old binding revoked and claims refused.
