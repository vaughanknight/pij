How each PR was proven

Plan before build

Unified plan (business spec + implementation plan) in one atomic pass, validated three times by cold peers before dispatch: NEEDS ATTENTION → 5 findings folded (a vacuous AC, a dropped wrapper arg, duplicate-registry ordering, dual backend, parked semantics) → NEEDS ATTENTION → 1 HIGH folded (agent-spawn plumbing unreachable) → path nits fixed. Two of those findings only a validator could see.

TDD with fakes, one packet per phase

The coder implements a whole phase per delegation packet, RED tests first, pathspec-mandatory commits, never pushes. Packets carry worktree, branch, base, allowed/forbidden paths, gate commands, and the wire discipline citation.

Cold cross-model review with Dim-0

A separate claude-opus-5 seat reviews at a frozen SHA it re-derives itself, runs every mutation named in the brief plus its own, restores byte-identical (cmp + git hash-object), and files a verdict. Two reviewers self-corrected earlier findings; one found its own harness had produced a false green and said so.

Orchestrator sanity pass

Before any approval: re-read the load-bearing hunk, confirm the verdict artifact exists, re-run a gate, check scope against the packet. Three phases were held back despite an APPROVE because the findings were real (items 1, 1b, 13, 15).

Incidents and recoveries

Reviewer wedged for 80+ minutes

The first reviewer's copilot turn hung after filing its verdict; four inputs (bg result, /compact, the re-review pointer, a status request) queued behind it. The daemon read working; the watchdog read “paused (compact)” for a compact that was only queued. Esc and Ctrl-C had no effect. Closed it, spawned a fresh cold reviewer after the freeze lifted, re-dispatched. → items 25.

False death on pane move

Moving the new reviewer into the team window with join-pane produced “has exited; terminal absence (unrequested-by-pij)” while it was alive and bound seconds later. → item 26.

Stale spine lock after restart #1

write.lock still named the dead daemon's pid; every seat's spine write failed until the o-prime removed it by hand, then events.lock blocked replay the same way. Reported with evidence from this seat within minutes. → item 15 (both layers).

Main went red under a sibling PR

Two skill-text tests failed on origin/main after PRs #7/#8; reproduced on a detached checkout, reported with the exact test names, routed to s392 as 9-FX; PR #9's body stated the pre-existing failures honestly rather than claiming green.

Dry run said clean, rebase conflicted

merge-tree on the branch tip predicts a squash merge, not a commit-by-commit rebase. Two rebases hit conflicts the dry run missed; one test-file merge was rebuilt deterministically from both parents when a hand merge left an unbalanced brace.

Future-dated “measured” stamp

Local calendar date concatenated with the UTC clock (both the coder and the orchestrator made the same slip independently). Corrected to the request-ID-decoded instant; encode: timestamps only from a clock call.

Duplicate delivery across restart #4

The same message appeared twice in a coder's transcript with a single sqlite row — an RPC-side replay, not a queue re-announce. Captured; idempotent this time.

Base move mid-build

Item 15's coder was building on a base without item 13's descriptor lock, which its task retrofits. Caught at merge time from the overlap check; the coder committed a WIP checkpoint (pathspec, never a bare stash) and rebased before continuing.
