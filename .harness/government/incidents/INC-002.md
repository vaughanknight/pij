# INC-002 — o-prime pathspec commit swept sibling's uncommitted fence work

**When**: 2026-07-12 ~00:00Z · **Who**: pij-3vetx8 (o-prime) · **Self-reported**: yes, caught at commit-stat read (234 insertions for a 2-line fix)

## What happened

During the CI trunk repair (prime integration test timeout), the o-prime took a
declared window on `cli.integration.test.ts` — a file inside s040's granted
fence — applied a 2-line fix, and committed it via pathspec (74628bb). The
pathspec was file-scoped, but the file also carried s040's uncommitted,
UNREVIEWED coder work; the commit swept all 234 lines of it onto local trunk.

## Repair

`git reset --soft HEAD~1` + unstage within two minutes; commit never pushed;
working tree verified intact (s040's hunks + the fix both present). Untangle
coordinated with s040 via the SW-5 reproducible-revert pattern (its work is
sha-pinned in review-input.patch).

## Lesson (encode candidate, INC-001 family third strike)

Pathspec discipline protects against staging OTHER files; it cannot protect
against uncommitted sibling hunks INSIDE a named file. Before committing any
file in a sibling's fence — even under a declared window — diff-stat the staged
change against the intended edit size; a mismatch is a stop. The mechanical
guard: `git diff --cached --stat` line-count sanity versus the announced edit
before every window commit.
